# 萤石 NAS 精简备份

**在访达里给文件夹打个标签，它就被纳管了。** 之后这个文件夹里的任何新增、修改、删除，都会单向镜像到 NAS；被改掉或删掉的旧文件进 `_versions/`，保留 30 天。

有一个**菜单栏 App**（`EzvizBackup.app`），也可以纯命令行用。

## 菜单栏 App

双击 `EzvizBackup.app` 即可，图标是**硬盘形状**，在菜单栏右侧第三方图标区（系统图标左边）。

点开是这样：

```

本次改动：新增 2 · 修改 0 · 删除 0
同步间隔：每天 03:30
已纳管 3 个文件夹
──────────────
立即同步                ⌘R
──────────────
备份文件夹              ▸   列出纳管的文件夹 / 在访达中显示 / 移除标签 / 添加文件夹… ⌘O
同步间隔                ▸   每小时 · 每天 · 每周 · 自定义… · 仅手动
──────────────
打开今天的日志
打开配置文件

```

- **添加文件夹…**（⌘O）弹出访达选择框，选中的文件夹自动打上标签，不用手动去访达点彩色圆点
- **同步间隔**选「自定义…」会开一个小窗口，可设频率 + 时间 + 星期
- 状态行是**灰色不可点**的，只是给你看

### 同步时能看到实时进度

同步进行中，图标会变成**旋转的循环箭头**，点开菜单会看到：


进度数据来自 `backup.sh` 写的 `.progress` 文件，所以**不管是 App 里点的「立即同步」
还是 launchd 半夜定时跑的，菜单栏都会实时显示**。

同步中会出现「停止同步」菜单项，点了会终止 rclone 并清理锁文件。

**开机自启**：系统设置 → 通用 → 登录项与扩展 → 点「+」添加 `EzvizBackup.app`

**改了脚本后要重新编译**：

```bash
./build-menubar.sh          # 只编译
./build-menubar.sh --run    # 编译并启动
```

> App 只是个**薄壳**：所有实际逻辑都在同目录的 shell 脚本里。
> 不装 App、直接用命令行完全一样，App 只是让你少敲字。

## 为什么是这样设计的

| 决定 | 原因 |
|---|---|
| 不在 NAS 上跑程序 | NAS 是 ARM 双核 + 256MB 内存 + 封闭固件，**不支持 Docker、不能刷机**，没有"装 App"这个入口 |
| 用「访达标签」决定同步范围 | 不用维护路径清单。打标签 = 纳入，去标签 = 停止同步（NAS 上的副本保留） |
| `rclone` 直连 SMB，不挂载网络盘 | 挂载盘会掉、要 GUI 会话、定时任务里不可靠；rclone 自己管重连重试 |
| 存**普通文件**，不用加密仓库 | 你在海康智存 App、Finder、电视上都能直接翻看取用，不依赖本工具存活 |
| 单向镜像 + `_versions` 而不是纯复制 | 删除会传递（NAS 始终是本地镜像），但旧版本留 30 天兜底 |
| 每次同步前用 `rclone check` 预演 | 精确算出会「新增/修改/删除」几个文件，而不是同步完才知道 |
| 源目录为空时**拒绝执行** | 防止硬盘没挂上时把 NAS 上的副本清空 |

已实测你这台设备（`10.0.0.9`，NetBIOS `MyNAS`，共享 `Public`）**支持 SMB2+**。

## 标签怎么用

同步范围**完全由标签决定**，你在 `config.env` 里的 `BACKUP_TAGS` 写哪个标签名，就监听哪个。

### 先把标签加进访达（做一次就够）

访达右键 → 「标签」里**只显示收藏标签**。用程序写扩展属性打上的标签不会自动出现在那里，
所以要先把「备份」登记进收藏：

```bash
./add-finder-tag.sh              # 加默认标签「备份」
./add-finder-tag.sh 项目          # 加自定义标签
./add-finder-tag.sh --list       # 看当前收藏标签
./add-finder-tag.sh --remove 项目  # 移除
```

跑完访达会重启一次，之后**右键任何文件夹 → 标签 → 备份** 就能直接点。

> 也可以手动加：访达 → 设置 → 标签 → 点「+」新建一个叫「备份」的标签。

### 标签可以打在家目录外

`/Applications/...`、`/Volumes/移动盘/...` 这些**家目录之外**的位置同样支持，
会同步到 NAS 的 `_external/` 下面。搜索默认是全盘（靠 `config.env` 里的 `SEARCH_PATHS` 控制，
留空即全盘）。

```bash
./tag.sh list                    # 列出所有带标签的项目，标出哪些会被同步
./tag.sh add ~/Desktop/素材       # 打标签（默认用 config.env 的第一个标签）
./tag.sh add /Applications/某软件/配置    # 家目录外也行
./tag.sh remove ~/Desktop/素材     # 去掉全部标签（NAS 上已同步的副本会保留）
./tag.sh show ~/Desktop/素材       # 看某个路径的标签
./tag.sh check ~/Desktop/素材      # 判断它会不会被同步
./tag.sh check                   # 列出当前全部会被同步的文件夹
```

几个要点：

- **只处理文件夹。** 给单个文件打标签不会同步它——把文件放进一个打了标签的文件夹即可。
- **嵌套自动去重。** 如果 `~/A` 和 `~/A/B` 都打了标签，只同步 `~/A`（`B` 已经在里面了），不会重复传。
- **去标签 = 停止同步，不会删 NAS 上的副本。** 想真删，用 `rclone purge`（见文末）。
- **标签改动 1 秒内生效**（靠 Spotlight 索引，已实测）。

## NAS 上的目录结构

镜像你本地的相对路径，一眼能对上：

| 本地 | NAS 上 |
|---|---|
| `~/Documents/项目` | `<备份根>/Documents/项目/` |
| `~/Desktop/作品图` | `<备份根>/Desktop/作品图/` |
| `~/`（整个家目录） | `<备份根>/_home/` |
| `/Volumes/移动盘/素材` | `<备份根>/_external/Volumes/移动盘/素材/` |
| 被改掉/删掉的旧文件 | `<备份根>/_versions/<日期>/<原相对路径>/` |

备份根默认是 `Public/MacBackup/<你的主机名>/`。

## 日常命令

```bash
./backup.sh                  # 按标签同步
./backup.sh --dry-run        # 空跑，只看会新增/修改/删除什么
./backup.sh --sources        # 列出当前纳管的文件夹
./backup.sh --status         # 上次结果 + 纳管范围 + NAS 上的备份
./backup.sh --verify         # 校验 NAS 副本和本地是否一致
./backup.sh --prune          # 只清理过期版本，不同步
./backup.sh --orphans        # 列出 NAS 上没有对应源的目录（不删）
./backup.sh --clean-orphans  # 删除上面那些（带体积显示和确认）
```

### 删掉本地文件夹后，NAS 副本怎么办？

**默认不会自动删。** 这是故意的：如果源文件夹"消失"是因为移动硬盘没挂上、
或网络盘掉线，自动删 NAS 副本就是灾难。

所以 NAS 上会留下**孤儿目录**。清理靠显式命令：

```bash
./backup.sh --orphans                          # 先看清楚有哪些
./backup.sh --clean-orphans                    # 全删（会显示体积并让你确认）
./backup.sh --clean-orphans Lightbox 项目        # 只删指定的几个
./backup.sh --clean-orphans --yes 路径          # 跳过确认（脚本/App 用）
```

几点说明：

- **`_versions/` 不受影响** —— 版本历史还在，那不是孤儿
- 删除**不进废纸篓**，是直接删
- 实现上只沿着「通向有效源的路径」逐层下钻，不会递归遍历整棵树
  （早期版本会全树列举，把这台 NAS 直接拖到超时）

## 还原

「名字」= NAS 上的相对路径，用 `--list` 查看。

```bash
./restore.sh --list                          # NAS 上备份了什么
./restore.sh --versions Documents/项目         # 看这个目录的历史版本
./restore.sh Documents/项目 ~/Desktop/还原      # 还原到 ~/Desktop/还原/Documents/项目/... 
./restore.sh --old 2026-10-08 Documents/项目 ~/还原
./restore.sh --diff Documents/项目             # 比对本地和 NAS 的差异
./restore.sh --file Documents/项目 src/main.py ~/还原
./restore.sh --path Documents/项目/src/main.py ~/还原
```

> 还原一律落到 `<目标目录>/<末级名>/`，不会散落在目标目录里。
> **先导到新目录确认，别直接盖回原位置。**

### 一定要做一次还原演练

**没验证过的备份等于没有备份。** 首次同步完成后今天就做：

```bash
./restore.sh --list                  # 确认 NAS 上真的有东西
./restore.sh Documents/项目 ~/Desktop/还原演练
open ~/Desktop/还原演练                # 能打开、文件数对得上，才算数
```

之后每季度重做一次。

## ⚠️ 必须知道的四件事

**1. 这不是"备份"，是"第二份副本"。**
NAS 是**单盘位**，盘坏了数据就没了，也没有 RAID。真正的备份要 3-2-1：三份数据、两种介质、一份异地。
**千万别在只同步到 NAS 之后就删本地文件。**

**2. 开了「排除规则」就不是逐字节镜像。**
`excludes.txt` 默认跳过 `node_modules`、`.venv`、`__pycache__`、`*.dmg` 等**可再生成**的东西。
想要严格镜像（一个字节都不漏），把 `config.env` 里改成 `USE_EXCLUDES=0`，代价是体积大很多。

**3. 增删改的数字是「比大小」算出来的。**
预演用 `rclone check --size-only`，不读文件内容（否则要下载全量，太慢）。
所以**大小相同、内容不同**的文件会被判为"未改动"。真实同步时 rclone 会按大小+时间戳判断，通常一致。

**4. Mac 睡眠时定时任务不会跑。**
launchd 会在醒来后补跑一次。想准点跑：

```bash
sudo pmset repeat wakeorpoweron MTWRFSU 03:10:00
```

## 性能（2026-10-08 有线局域网实测）

**大文件，每次校验目标真为空、传完确认真有文件：**

| 场景 | 实测 |
|---|---|
| rclone 1 线程 | 5.6 MB/s |
| **rclone 2 线程（当前配置）** | **8.5 MB/s** |
| rclone 3 线程 | 约 9~10 MB/s |
| 海康智存 App（官方限 2 线程） | 约 11 MB/s |
| **百兆口物理上限** | **11.2 MB/s** |

**结论：**

- **同样 2 线程，rclone 比 App 慢约 25%**（8.5 vs 11）。因为 rclone 用的是纯 Go 重写的
  SMB 协议栈（go-smb2），单连接的请求流水线不如系统原生客户端和海康自己的 App。
- **但 rclone 不受 2 线程限制**，开 3~4 线程就能追平 App。
- **谁也超不过 11.2 MB/s** —— 那是百兆网口的物理天花板，跟软件无关。

### ⚠️ 小文件会慢得多

上面都是大文件的成绩。**小文件多的话完全是另一个世界**：

> 实测 192MB 分散在 **400 个小文件 / 20 个目录**里，花了 **439 秒 = 0.4 MB/s**。

因为每个文件都要一次完整的 SMB 往返，延迟吃掉了一切。代码仓库、素材库这类
"文件多而小"的数据，体感会比大文件慢一个数量级。

### 为什么不建议调大并发

| 配置 | 峰值 SMB 连接 | 结果 |
|---|---|---|
| `TRANSFERS=3` + `CHECKERS=6` + 多线程流 4 | **9 条** | 大量文件夹失败 |
| `TRANSFERS=2` + `CHECKERS=2` + 多线程流 0 | **1~3 条** | 稳定 |

`--multi-thread-streams` 默认是 4，意思是**每个大于 256MiB 的文件额外开 4 条并行流**，
每条流就是一条独立 SMB 连接。3 个传输 × 4 条流 = 12 条，直接把这台 256MB 的设备压垮。

`backup.sh` 里加了**护栏**：万一把这些值调大，启动时会打印警告说明风险。

## 资源不足问题：成因与处置

NAS 是 **256MB 内存**的嵌入式设备，SMB 服务是**厂商自己写的**（不是原版 Samba，
它的 Web 服务头是 GoAhead 系的 `REST-Webs`）。压力大时它会返回：

```
ERROR : couldn't initialize SMB: response error:
        Insufficient system resources exist to complete the API.
```

**症状**：速度从 9 MB/s 崩到几十 KB/s；某些文件夹报失败；严重时整个 SMB
不再响应（连列目录都要等 20 秒）。停下来几秒到几分钟会自愈。

### 排查过程中被证伪的两个猜测

| 猜测 | 实测结果 |
|---|---|
| "连接数太多" | ❌ rclone 同时只持有 **2~4 条** TCP 连接 |
| "会话开关太频繁" | ❌ 快速开关 30 次会话，**0 失败** |

### 真正的原因

统计 46 次错误，**37 次是 `couldn't initialize SMB` + `Failed to create file system`**
—— 失败发生在**建立新会话**那一刻，不是传输也不是列目录。

`--multi-thread-streams` 默认值是 **4**，含义是「每个大于 256MiB 的文件额外开 4 条并行流」，
**每条流就是一条独立 SMB 连接**。3 个传输 × 4 条流 = 12 条连接，直接把设备压垮。

> ⚠️ 注意：rclone 的 `--max-connections` 是 **HTTP 后端**的选项，对 SMB **无效**，
> 不要用它来"限制连接数"（我踩过这个坑）。

### 处置（已写进 config.env）

```bash
TRANSFERS=2                 # 并发传输数
CHECKERS=2                  # 并发目录扫描数
MULTI_THREAD_STREAMS=0      # 关掉多线程流 ← 最关键
SMB_IDLE_TIMEOUT=15m        # 会话复用，少建新会话
```

效果：峰值 SMB 连接从 **9 条降到 1~3 条**，速度反而更稳（不再边传边挣扎）。
`backup.sh` 里有**护栏**，把这些值调大时会打印警告。

残余风险仍在（固件本身的脆弱性），由 **失败自动重试**兜底：失败的文件夹会等待
30 秒后自动重试一轮，实测多次把 3 个失败全部补回。

### 如果 NAS 卡住了

```bash
pkill -9 -f rclone     # 杀掉挂起的进程
sleep 10               # 等 NAS 释放会话
rclone lsd ezviz:      # 验证，应该 0~1 秒返回
```

## 排除规则的坑（已实测）

写 `excludes.txt` 时：

| 写法 | 效果 |
|---|---|
| `目录名/**` | ✓ 匹配任意层级（含根层） |
| `**/目录名/**` | ✗ **只匹配嵌套层，根目录层会漏掉** |
| `目录名` | ✗ 完全不匹配（rclone 按文件路径匹配，不认裸目录名） |
| `文件名` / `*.后缀` | ✓ 匹配任意层级 |

改完规则先 `./backup.sh --dry-run` 确认，别让该备份的东西被悄悄跳过。

## 故障排查

**同步了 0 个文件夹**
`./tag.sh check` 看有没有命中标签。标签名要和 `config.env` 里的 `BACKUP_TAGS` **完全一致**（大小写、全半角）。
系统自带颜色标签在中文系统里叫「蓝色」「红色」，英文系统叫 `Blue`、`Red`。

**标签打了但读不到**
访达标签靠 Spotlight。检查索引状态：`mdutil -s /`，没开就 `sudo mdutil -i on /`，然后等几分钟。
外接硬盘如果关了这个卷的索引，就用 `config.env` 里的 `EXTRA_SOURCES` 直接写路径。

**连不上 NAS**
IP 可能变了。路由器里找 `MyNAS`，改 `config.env` 的 `NAS_HOST`，或给它设 DHCP 保留。

**速度只有 2~3 MB/s**
检查 Mac 是不是走的 WiFi。NAS 是百兆口，**尽量有线**；也试试调大 `TRANSFERS`。

**想彻底停掉或清空**

```bash
./install-launchd.sh --uninstall                     # 停掉定时任务
./tag.sh remove <文件夹>                              # 停止同步某个文件夹（NAS 副本保留）
rclone purge "ezviz:Public/MacBackup/<主机名>"          # 清空 NAS 上的备份（谨慎！）
rm -f ~/.config/rclone/rclone.conf                   # 删除凭据
```
