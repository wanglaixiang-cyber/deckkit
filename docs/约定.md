# deckkit 约定

给想加新服务的人（包括未来的你）。

---

## 1. 目录约定

```
services/<服务名>/
├── SERVICE.md     第一行 = 一句话说明（deck list 读它）
├── service        入口脚本，必须可执行，必须实现 status
├── mac/           Mac 侧的东西（引擎、App、配置）
└── deck/          Deck 侧的东西（代理、安装脚本、root 配置）
```

服务名用小写字母和连字符。**不要**在服务目录里放跨服务共享的东西 ——
那种东西放框架根目录。

### 1.1 源码可以放在框架外面

`services/<服务名>/` 只该放「**怎么管这个服务**」。如果这个服务其实是一个
**已有独立仓库的项目**（有自己的 `.git`、自己的发布节奏），把源码搬进来会很难受：
框架仓库里套着另一个仓库，`git add` 只会记一个 gitlink，等于框架的版本库
不覆盖这块；两边提交也容易搞混。

正确做法是分层，用 `mac/config.env` 里的 `PROJECT_DIR` 指过去：

```
deckkit/services/<服务名>/          ← 只放怎么管
├── SERVICE.md
├── service                         ← 里面用 PROJECT_DIR 找源码
├── mac/config.env                  ← PROJECT_DIR="/path/to/the/project"
└── deck/

/path/to/the/project/               ← 项目自己的仓库，自带 .git
```

框架里就有这么做的服务。判断标准很简单：
**这段代码离开 deckkit 还能独立存在吗？** 能，就别搬进来。

## 2. 入口脚本约定

`services/<服务名>/service`：

```bash
#!/usr/bin/env bash
set -uo pipefail
SVC_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

case "${1:-status}" in
  status)  echo "一行人类可读的摘要" ;;   # ← 必须实现
  ...)     ... ;;
  -h|--help|help|"") sed -n '2,12p' "$0" | sed 's/^# \?//' ;;
  *) die "不认识子命令：$1" ;;
esac
```

规则：

- **`status` 必须实现**，且输出**人类可读**的摘要。`deck` 概览取它第一行非空内容。
- 状态输出尽量带符号：`✓` 正常 / `!` 注意 / `✗` 出错。
- 需要「立刻返回」的长任务，用 `--async` 风格的开关，别让调用方干等。
- 配置文件放 `mac/config.env`，键名大写下划线；脚本里用
  `sed -n 's/^KEY=//p'` 之类的方式读，避免 `source`（那会污染环境）。

### 2.1 可选的契约子命令

框架和菜单栏会用到下面三个，按需实现：

| 子命令 | 作用 | 关键约定 |
|---|---|---|
| `ensure` | **幂等自愈**：把服务弄成正常状态 | **一切正常时不输出任何内容**，只在真的动手时打印 |
| `toggle` | 用户主动**切换主状态** | 只有声明了才生效。例如 `files` 是挂载 ↔ 卸载 |
| `caps` | 一行一个列出实现了哪些可选子命令 | 格式 `<子命令> [一句说明]`。框架靠它决定「点一下」是切换还是看详情、`ensure` 该不该调它，不靠猜 |
| `help` / `help-all` | 给终端用的**命令清单** | `help` 输出最常用的几条（每行以 `deck` 开头，框架直接展示）；`help-all` 输出完整用法。框架的 `deck help` 会按服务分段展示各服务的 `help`，所以**常用的放 help、完整的放 help-all**，不要一股脑堆出去 |
| `pick` | **点一下先弹系统文件选择器**，选中的文件作为参数传给声明的子命令 | `caps` 里写 `pick <按钮提示>\t<子命令>[\t<扩展名,..>]`（tab 分隔，第三列可选）。框架跑 `deck <服务> <子命令> '<选中文件>'`。用于「给我一个文件，剩下的我自己判断」这类服务（`patches` 就是：选补丁 exe → 自己找游戏 → 挂载；`games` 是：选安装包**或免安装游戏的目录** → `add`）。选择器的文案取自第一列，所以**别在图省事写「选择文件」**；第三列是文件类型过滤（不写或写 `*` = 不限）。**要允许选文件夹就写上 `dir`** —— 菜单栏按它决定文件夹是否可选：`patches` 要选补丁文件夹所以写了 `dir`，`games` 改成「必须选主程序 exe」所以没写（文件夹是灰的）。菜单栏那边把扩展名解析成 `UTType` 再塞给选择器，并且**总是额外放行文件夹** —— 补丁文件夹、免安装游戏目录都得靠选文件夹 |

三点设计原因：

1. **`ensure` 必须正常时静默** —— 框架/菜单栏拿「有没有输出」判断这次到底修没修东西，
   进而决定要不要重新取一遍状态。要是它每次都打印「一切正常」，就会白跑一轮。
2. **能力要显式声明**（`caps`），不要靠行为试探 —— `deck toggle <服务>` 会先问 `caps`，
   没声明就直接报错退出，而不是真去切一下看看会发生什么。对「切换 = 停掉爬虫」的
   服务，误触的代价太大。`ensure` 同样只对声明了它的服务调用。
3. **`toggle` 必须把用户的意图记下来** —— 因为 `ensure` 会**每轮刷新都跑**
   （挂载会自己掉，实测 Deck 一直在线也会掉，只在启动时补是不够的）。
   所以服务要写一个「期望状态」标记，`ensure` 先读它再决定动不动手：
   否则用户点一下卸载，下一轮就被自动挂回去 —— 手动操作永远不生效。

   `files` 的做法：手动卸载/挂载时写 `~/Library/Application Support/deckkit/files.want`
   （`on`/`off`），`ensure` 见到 `off` 就直接返回。

## 3. 两机协作约定

### 连接

| 方向 | 手段 | 前提 |
|---|---|---|
| Mac → Deck | `ssh deck`（`~/.ssh/config` 别名，`AddressFamily inet`） | Deck 开 SSH |
| Deck → Mac | `ssh mac`（同上） | **Mac 开「远程登录」** |

**`AddressFamily inet` 是必须的**：`*.local` 的 AAAA 记录常常存在但不可达，
不强制 IPv4 的话每次连接都会先试 IPv6、白等约 5 秒。

**连接必须复用。** 一次菜单栏刷新要开 6~8 个 SSH 连接（遥测一次，每个服务的
`status` 内部还有好几次），**每次重新握手约 0.19 秒** —— 不复用的话一轮 2.6 秒，
用户看到的就是「状态更新慢半拍」。加上这三个选项即可：

```bash
-o ControlMaster=auto
-o ControlPath="$HOME/.ssh/deckkit-cm-%r@%h:%p"
-o ControlPersist=15s          # 一轮刷新内的调用都能复用，刷完就断，不留常连
```

实测：一轮刷新 **2.6 秒 → 0.3 秒**；连续 3 次 ssh 调用 0.56 秒 → 0.07 秒。
deckkit 的脚本各自在 `SSH_MUX` 数组里带了这几个选项（不依赖用户的 `~/.ssh/config`）。

`ControlPersist` 不要设太长：刷新间隔是 30 秒，设成 60 秒会让连接一直挂着，
相当于对 Deck 保持一条常连。

### 触发在 Deck、执行在 Mac

涉及「Mac 上的数据」的任务，让 Deck 只发信号、Mac 自己执行。
理由：Mac 才是数据所有者（比如访达标签清单只在 Mac 上），
Deck 不需要知道业务细节，只要能说「我醒了」。

### 请求一律异步

```bash
ssh mac 'wake-helper.sh --trigger=wake --async'      # 历史示例，脚本随 backup 服务退役
```

Deck 随时可能休眠断网。让 SSH 连接只维持到「请求被接受」，
真正耗时的活儿丢到 Mac 后台 —— 否则连接一断，任务状态就乱套了。

异步入口必须做**并发去重**（拿锁 / 判断已在跑就直接返回 0），
因为 Deck 的开机触发和唤醒触发可能挨得很近。

### 时钟差法检测休眠

Deck 上检测「刚从休眠唤醒」不要用 D-Bus（普通用户订阅 system bus 会被降级成
eavesdropping，不可靠），用时钟差：

```python
CLOCK_MONOTONIC   休眠时【停走】
CLOCK_BOOTTIME    休眠时【继续走】
# 两次采样间若 (ΔBOOTTIME - ΔMONOTONIC) >= 阈值 → 刚醒
```

纯用户态、零权限（已退役的 `backup` 服务当年就是这么做的，代码在 `_archive/`）。

## 4. Deck 侧约定

### systemd 用户服务

- 单位名：`deckkit-<服务名>.service`
- 放 `~/.config/systemd/user/`，用 `systemctl --user enable --now` 启动
- **不要**用系统级服务 —— 那需要 root，而且 `/usr` 会被 SteamOS 更新替换

### 文件位置

| 内容 | 位置 | 为什么 |
|---|---|---|
| 入口脚本 | `~/bin/deckkit-<服务名>-*` | 在 PATH 里，`ssh deck` 能直接调 |
| 服务源码 | `~/deckkit/services/<服务名>/` | 和 Mac 侧结构对称 |
| 日志 | `~/deckkit-<服务名>.log` | 用户目录，持久 |
| 需要 root 的配置 | `/etc/...` | **注意**：`/etc` 是 overlay，SteamOS 大版本更新会清掉 |

### root 操作

写一个 `provision-root.sh` 之类的脚本，**用 `sudo -n`（免密）**，
检测失败就明确提示怎么授权，不要交互式等待。

免密 sudo 的授权由用户在 Deck 上一次性完成（Deck 没有键盘鼠标时，用
`ssh -t deck` 从 Mac 把密码提示透传回来）—— **任何需要人敲东西的步骤都应该从 Mac 发起**：

```bash
ssh -t deck 'echo "deck ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/zz-deck-nopasswd >/dev/null; sudo chmod 440 /etc/sudoers.d/zz-deck-nopasswd'
```

`/etc/sudoers.d/` 里的文件名要用 **`zz-` 前缀**：sudoers 规则是
「最后匹配的生效」，而 drop-in 按文件名字典序读取，`010-` 排在 `wheel`
前面会被它覆盖。

## 5. Mac 侧约定

- 图形界面启动的进程 **PATH 很窄**，不含 `/opt/homebrew/bin`。
  脚本里显式补 PATH，否则找不到 brew 装的工具。
- 网络探测放**后台队列**，并加超时（非阻塞 connect + `poll`），
  绝不能在主线程上做同步网络调用 —— 菜单栏会卡死。
- 长任务入口（被 Deck 调用的那些）必须先拿锁再执行。
- **服务端渲染 / 后台任务发起的请求，用的是「服务端进程的网络身份」**，
  不是浏览器、也不是你敲命令的那个 shell。所以：
  - 配置里的地址要按「这台机器上的那个进程能不能访问到」来定；
  - **自检必须用「和那个进程同一个二进制」**：`curl`/`nc`/`ssh`/`python3` 是
    Apple 自带二进制，**不受 macOS「本地网络」权限限制**，拿它们探会得到相反的
    结论（这个坑让我们白查了好几轮，还一度推翻了正确结论）。要探前端就用 `node` 探。
  - 别拿「我 curl 得通」证明「页面能取到数据」—— 要端到端测一次
    （做法：doctor 里真去请求一次那个页面看 SSR 有没有数据）；
  - 报错一定要把底层 cause 带出来（`fetch failed` 本身不含信息量），
    否则排查会退化成猜，甚至猜出一个错误的根因然后为它写出绕路代码。
- **macOS「本地网络」权限**（macOS 15 起）：第三方二进制想连同网段主机，必须由
  「启动它的那个 App」拿到这个权限，否则 `connect()` 立刻 `EHOSTUNREACH`
  （errno 65，静默失败、不弹窗、不写日志）；网关和回环不受影响，Apple 自带
  二进制也不受影响。所以「从 shell 里一切正常、只有前端连不上」是它的典型长相。
  注意它**按 Mach-O UUID / bundle id 解析身份**：解析不到 bundle id 的上下文
  （比如终端）在系统设置里**连条目都不生成**，也就无法授权 —— 这种情况不要
  折腾那个列表。
- **拿不到权限就借有权限的 App**：框架里 `menubar/DeckKit.app` 是常驻的，并且
  已获本地网络权限，所以「由它启动的 node」是通的。约定做法：需要局域网的服务
  在启动网络子进程前，先探一次当前上下文（**用和子进程同一个二进制探**），
  探不通就写一个请求文件 + `open -a <App> <文件>`，由 App 以自己的身份代跑
  （借用菜单栏 App 身份的那个 `ask_menubar_web_start` 就是这么做的；子进程带
  `DECKKIT_WEB_INAPP=1` 防递归）。父进程决定权限，**不要**改用常驻隧道绕。
- **休眠/唤醒是菜单栏状态的唯一「无声过期」来源**：Timer 睡眠期间不走，
  醒来只补一次。要订阅 `NSWorkspace.willSleepNotification` /
  `didWakeNotification`（token 必须持有），醒来立刻刷一次。

## 6. 安全阀优先

任何「会根据 Mac 的状态去删除 Deck 上东西」的逻辑，都要有退化保护。
三道阀（来自已退役的 backup 服务，原则通用）：

1. **清单为空** → 直接退出，什么都不做
2. **源不存在** → 跳过这一项
3. **源为空** → 跳过这一项

判断「空」要递归判断（`find "$SRC" -type f -print -quit`），
因为「目录里没文件」通常意味着磁盘没挂上或同步还没开始，而不是真的清空了。
**宁可不同步，也不要误删备份。**

同理，任何会**覆盖** Deck 上数据的操作（换数据库、换二进制），
都要先把现状另存一份再动手 —— 例如 `files` 的 install/restore
都会先留一份 `pre-restore` 快照。

## 7. 踩过的坑（别重复踩）

| 坑 | 表现 | 解法 |
|---|---|---|
| IPv6 白等 | 每次 ssh 慢 5 秒 | `AddressFamily inet` |
| 非交互 SSH 的 PATH | `ssh host 'cmd'` 找不到 brew 的命令 | 脚本里显式设 PATH |
| sudoers 顺序 | `010-xxx` 写了 NOPASSWD 却仍要密码 | 用 `zz-` 前缀 |
| NFS 属性缓存 | 绕过 NFS 写入的文件 Mac 约 60 秒后才看见 | 知情即可；重要判断前先 `stat` 一下 |
| AppleDouble | macOS 往 NFS 写会生成 `._xxx` 陪衬文件 | 同步后扫掉（`excludes.txt` 拦不住内核写的） |
| mDNS 名字的 AAAA | Python/Swift 里只解析 IPv4 | `AF_INET` |
| SSH 超时 < 任务时长 | 误判失败并重复触发 | 改异步，或把超时设得比任务长 |
| SteamOS 更新重置 `/etc` | sudoers / NFS 配置丢失 | 重跑对应 provision 脚本即可 |
| **全角字符紧跟 `$VAR`** | macOS 自带 bash 3.2 会把全角标点的字节吃进变量名，报 `unbound variable` | 一律写 `${VAR}`。Deck 上是 bash 5 不受影响，所以这个坑**只在 Mac 侧脚本**里暴露。`deck doctor` 会扫一遍所有脚本（越过纯注释行），别再手工找了 |
| **`set -u` + 空数组** | bash 3.2 展开 `"${arr[@]}"` 报 unbound variable | 改用标量，或写 `"${arr[@]+"${arr[@]}"}"` |
| 全角括号 + 变量拼接 | `"（$VAR）"` 想当然能工作 | 同上，写 `"（${VAR}）"` |
| 不复用 SSH 连接 | 菜单栏刷新慢半拍（一轮 2.6 秒） | `ControlMaster=auto` + `ControlPersist=15s` → 0.3 秒 |
| **改了 `NEXT_PUBLIC_*` / 挪了 Next.js 项目却不清 `.next`** | 页面报 `fetch failed`：缓存里存着旧绝对路径，还会吐出内联了**旧环境变量**的 chunk —— 症状和「后端挂了」一模一样 | `web start` 用一个标记文件记住「项目路径 + 后端地址」，变了就自动清 `.next` 并重启前端。构建缓存里既有路径也有内联的环境变量，**搬家或改地址都得清** |
| 菜单栏点一下却只看到状态 | 用户以为「点了没反应」 | 动作和详情都放终端里跑，进度实时可见 |
| `ssh -t` 在无终端环境失败 | 菜单栏/CI 调用 `ssh -t` 直接报错 | 只在 `[ -t 0 ]` 时加 `-t` |
| `scp` 传含 `~` 的路径 | SFTP 后端不保证展开 `~`，可能写进名为 `~` 的目录 | 先 `scp` 到 `/tmp`，再由远端脚本 `mv` 到位 |
| **`"${VAR#~/}"` 剥不掉前导 `~`** | 想剥掉 `~/` 却原样保留，拼出 `$HOME/~/...` 这种路径 | bash **也会**对 `${var#word}` 里的 word 做 tilde 展开（`~/` 被展开成 `$HOME/` 于是匹配不上）。写 `${VAR#\~}`。另注：参数以 `~` 开头时，远端 shell 在 bash 看到它之前就已经展开了，所以远端脚本里这种兜底通常根本不会触发 —— 触发就是错的 |
| **后台子进程继承调用者的 stdout** | `deck xxx web start \| tail` 之类的命令**永远不返回**（实测挂死 3 分钟） | `nohup cmd >>log 2>&1 </dev/null &` 只摘掉了 stdin。启动后台进程的那段要整体重定向：`( ... & ) >/dev/null 2>&1` |
| **`cfg_get` 里用 `xargs` 去空白** | 值里有单引号时 xargs 报错；连续空格被折叠；引号被当成语法吃掉 | 用 `sed 's/^[[:space:]]*//; s/[[:space:]]*$//'` |
| **`.local` 名字的解析可能要 5 秒** | `dscacheutil -q host -a name steamdeck.local` 在主机在线时也可能等满 5 秒 | 只在**手动命令**里解析（如 `doctor`）；运行路径上（菜单栏刷新、定时探测）用 IP |
| **macOS「本地网络」权限** | 「服务在线但页面连不上」：前端进程连同网段主机 `EHOSTUNREACH`（瞬间失败），而**同一个地址**用 `curl`/`nc`/`ssh`/`python3` 都通、网关和回环也通 | 权限按**启动它的 App** 判定；终端这种解析不到 bundle id 的上下文在系统设置里连条目都不生成。做法是借有权限的常驻 App（`menubar/DeckKit.app`）代跑，父进程决定权限（`ask_menubar_web_start`） |
| **用 `curl` 自检「前端能不能连后端」** | 得到与事实相反的结论（curl 是 Apple 自带二进制，不受本地网络权限限制），据此推翻正确诊断、白查好几轮 | 探谁就用谁的二进制：探前端 SSR 就用 `node` 探，端到端再请求一次搜索页 |
| 常驻 SSH 转发（隧道） | 「给服务加个隧道绕开网络问题」很诱人，但对 Deck 保持常连、多一个会自己挂掉的进程，且掩盖真实原因 | 先拿到**对照实验**级别的证据；能用「借有权限的 App 代跑」解决就别加常驻进程。本项目当前不留常连（`ControlPersist=15s`），也没有隧道 |

## 改动纪律：先想连带影响，再动手

这一节是被真实事故逼出来的，核心就两句：**改一处之前先问"谁依赖它"，改完立刻实测一次。**

### 真实事故（同一天内发生的，都是同一个病）

| 改动 | 当时的想法 | 实际连带影响 |
|---|---|---|
| 往 `find-game-exe` 的排除表里加 `/Steam/` | "排除 Proton 自己的 `steam.exe`" | `grep -viE` 是**不分大小写**的，`/Steam/` 匹配上了 `~/.steam/steam/steamapps/…` —— 这段**每个 prefix 路径里都有** → 所有 exe 被滤掉 → `finish` 找不到主程序 → 记录与 Steam 注册全丢 |
| 删掉"安装器状态判据"整段 | "删掉多余的等待逻辑" | 顺手把同一段里的 **Ctrl-C trap** 一起删了；而注册挂在 `finish` 后面、`finish` 又挂在阻塞调用后面 —— 用户 Ctrl-C 一次，收尾和注册全丢 |
| 用正则替换 `cmd_restore` 的实现 | "只改这一个函数" | 把夹在中间的 `cmd_remove` 一起删了 → `shortcut-remove` 直接 `NameError` |
| 改"写完回读确认"的 glob | "只是换个写法" | 少了一个 `/`，glob 失效 → 明明写成功却报「回读不到」，白折腾一轮 |
| 用"合并所有备份"帮用户找回过丢失的条目 | "数据丢了就合并回来" | 把用户**主动删掉**的条目也复活了 —— 在用户视角里就是"你乱动我的列表" |

### 动手前先问五个问题

1. **谁依赖它？** —— 尤其是含 `grep -i` 的排除项/白名单：**先用真实路径跑一遍**再提交
2. **我删的这段里还有什么？** —— 删之前把整段读一遍，不要按标题删（trap、提示、别的函数都可能夹在里面）
3. **有没有第二处要同步改？** —— 例如改了 `meta.tsv` 的键名，所有读它的地方都要跟着改
4. **失败路径会怎样？** —— 阻塞调用被 Ctrl-C、文件被别的程序覆盖、路径不存在时：是**明确报错**，还是**静默丢结果**？（宁可吵，不可哑）
5. **这份数据是谁的？** —— 用户的 Steam 列表、游戏存档、原始补丁包：**宁可不动，也不要"帮忙恢复"**

### 改完必须做的三件事

1. **实测那条路径**（不是"看起来对"）：能真跑就真跑一次；不能真跑就把改动点和真实数据对一遍（例如把过滤规则和真实文件路径对一遍）
2. **确认补丁真的落地**：`grep` 改动点；锚点没匹配上就**当失败处理**，别默认成功
3. **确认部署的副本是新的**：本地改了 ≠ Deck 上是新的（`install-here` 要跑，跑完再 `grep` 确认一次）
4. **判断"成功了没"要用不会骗人的信号** —— 别拿日志行数当判据：不设 `PROTON_LOG` 时 Proton 会把
   `DXVK_LOG_LEVEL` 设成 `none`，DXVK 一行都不打，实测"日志只有 2 行"的那几次其实已经渲染出窗口、
   game.exe 跑到 15% CPU（为此白查了一小时）；也别用 `strings \| grep 名字` 查二进制里的日文
   （`strings` 只输出 ASCII 串，必然查不到 → 会误报"没写进去"）。要么看窗口/CPU/退出码这种硬信号，
   要么把判据写在**不依赖编码、不依赖日志等级**的地方（例如按 appid 解析文件）
