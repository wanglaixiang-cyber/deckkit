# deckkit 约定

给想加新服务的人（包括未来的你）。**加新服务前先读 §1、§2**，其余按需翻。

> 这份文档只写**跨服务、跨语言**的东西。某个服务自己的坑、边界、实测过程写在
> 那个服务的 `SERVICE.md` 里 —— 别往这里堆，两边重复的代价是改一处忘一处。

---

## 1. 目录约定

```
services/<服务名>/
├── SERVICE.md     第一行 = 一句话说明（deck list 读它）
├── service        入口脚本，必须可执行，必须实现 status
├── mac/           Mac 侧的东西（引擎、App、配置）
└── deck/          Deck 侧的东西（代理、安装脚本、root 配置）
```

服务名用小写字母和连字符。

**跨服务共享的东西一律放框架根 `bin/`**，不许在服务目录里放、更不许抄第二份：

| 文件 | 作用 |
|---|---|
| `bin/deck` | 统一 CLI（分发 + 内建运维命令 + 各服务命令清单） |
| `bin/deck-lib` | 公共库：颜色与消息、`cfg`、SSH 复用与 `rsh*`、`slug`、日志、`usage`、Deck 侧通用件 |
| `bin/deck-log` | 统一日志入口（位置/格式/滚动定在一处） |

接公共库（服务入口的固定开头）：

```bash
SVC_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
MAC_DIR="${SVC_DIR}/mac"; DECK_DIR="${SVC_DIR}/deck"
DECKKIT_ROOT="$(cd "$SVC_DIR/../.." && pwd)"
. "${DECKKIT_ROOT}/bin/deck-lib"      # 只有定义、没有副作用，可重复 source
```

Deck 侧的脚本接 `~/deckkit/bin/deck-lib`（由各服务的 install 一起推上去），
**库缺失时要能降级继续跑**（日志和库都是辅助，不该让服务起不来）。

### 1.1 源码可以放在框架外面

`services/<服务名>/` 只该放「**怎么管这个服务**」。如果这个服务其实是一个
**已有独立仓库的项目**（有自己的 `.git`、自己的发布节奏），把源码搬进来会很难受：
框架仓库里套着另一个仓库，`git add` 只会记一个 gitlink，等于框架的版本库
不覆盖这块；两边提交也容易搞混。

正确做法是分层，用 `mac/config.env` 里的 `PROJECT_DIR` 指过去：

```
deckkit/services/<服务名>/          ← 只放怎么管
├── SERVICE.md
├── service                         ← 里面用 PROJECT_DIR 找源码
├── mac/config.env                  ← PROJECT_DIR="/path/to/the/project"
└── deck/

/path/to/the/project/               ← 项目自己的仓库，自带 .git
```

框架里就有这么做的服务。判断标准很简单：
**这段代码离开 deckkit 还能独立存在吗？** 能，就别搬进来。

## 2. 入口脚本契约

每个服务的 `service` 至少要有一个 `status`：

```bash
#!/usr/bin/env bash
# ============================================================
#  deckkit / <服务名> —— 服务入口
#
#    deck <服务名> status      一行状态（必须实现，见下）
#    ...                       别的子命令
# ============================================================
set -uo pipefail
SVC_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
. "$SVC_DIR/../../bin/deck-lib"

case "${1:-status}" in
  status)  ok "一行人类可读的摘要" ;;        # ← 必须实现
  ...
  -h|--help|help|"") usage ;;               # 公共库的 usage：本文件头部注释块
  *) die "不认识子命令：$1" ;;
esac
```

规则：

- **`status` 必须实现**，输出**人类可读**的摘要。`deck` 概览、`deck brief` 和
  菜单栏都取它**第一行非空内容**当这一行的摘要 —— 所以第一行要能独立成立。
- 状态输出带符号：`✓` 正常 / `!` 注意 / `✗` 出错。
- 头部注释块就是 `usage`（第 2 行到第一个非注释行）。**别把行号写进脚本**
  （`sed -n '2,20p'` 这种：头注释一变 usage 就被切断），用公共库的 `usage`。
- 配置放 `mac/config.env`，键名大写下划线；用 `deckkit_cfg` / `deckkit_cfg_or`
  读，**不要 `source`**（那是拿人看的文本当可执行代码，会污染环境）。

### 2.1 可选的契约子命令

框架和菜单栏会用到下面这几个，按需实现：

| 子命令 | 作用 | 关键约定 |
|---|---|---|
| `ensure` | **幂等自愈**：把服务弄成正常状态 | **一切正常时不输出任何内容**，只在真的动手时打印 |
| `toggle` | 用户主动**切换主状态** | 只有声明了才生效。例如 `files` 是挂载 ↔ 卸载 |
| `caps` | 一行一个列出实现了哪些可选子命令 | 格式 `<子命令> [一句说明]`。框架靠它决定「点一下」是切换还是看详情、`ensure` 该不该调它，**不靠猜** |
| `help` / `help-all` | 给终端用的**命令清单** | `help` 输出最常用的几条（每行以 `deck` 开头，框架直接展示）；`help-all` 输出完整用法。**常用的放 help、完整的放 help-all** |
| `pick` | **点一下先弹系统文件选择器**，选中的文件作为参数传给声明的子命令 | `caps` 里写 `pick <按钮提示>\t<子命令>[\t<扩展名,..>]`（tab 分隔，第三列可选，写 `dir` 表示允许选文件夹）。框架跑 `deck <服务> <子命令> '<选中文件>'`。选择器文案取自第一列，所以**别写「选择文件」这种废话** |

三点设计原因：

1. **`ensure` 必须正常时静默** —— 框架/菜单栏拿「有没有输出」判断这次到底修没修
   东西，进而决定要不要重新取状态。每次都打印「一切正常」就会白跑一轮。
2. **能力要显式声明**（`caps`），不要靠行为试探 —— `deck toggle <服务>` 会先问
   `caps`，没声明就直接报错退出，而不是真去切一下看看会发生什么。
   对「切换 = 停掉爬虫」的服务，误触的代价太大；`ensure` 同样只对声明了它的服务调用。
3. **`toggle` 必须把用户的意图记下来** —— 因为 `ensure` 会**每轮刷新都跑**
   （挂载会自己掉，实测 Deck 一直在线也会掉，只在启动时补是不够的）。
   服务要写一个「期望状态」标记，`ensure` 先读它再决定动不动手：否则用户点一下卸载，
   下一轮就被自动挂回去 —— 手动操作永远不生效。
   `files` 的做法：写 `~/Library/Application Support/deckkit/files.want`（`on`/`off`）。

## 3. 两机协作

### 连接

| 方向 | 手段 | 前提 |
|---|---|---|
| Mac → Deck | `ssh deck`（`~/.ssh/config` 别名，**必须** `AddressFamily inet`） | Deck 开 SSH |
| Deck → Mac | `ssh mac`（同上） | Mac 开「远程登录」 |

`AddressFamily inet` 不是可选优化：`*.local` 的 AAAA 记录常常存在但不可达，
不强制 IPv4 的话每次连接都要先白等约 5 秒（`deckkit` 自己的脚本一律走 IP 或别名，
不解析 mDNS 名字）。

**连接必须复用。** 一次菜单栏刷新要开 6~8 个 SSH 连接，每次重新握手约 0.19 秒 ——
不复用一轮 2.6 秒，用户看到的就是「状态更新慢半拍」。三个选项（公共库的
`deckkit_ssh_init` 已经带上，不要自己拼）：

```bash
-o ControlMaster=auto
-o ControlPath="$HOME/.ssh/deckkit-cm-%r@%h:%p"
-o ControlPersist=15s          # 一轮刷新内的调用都能复用，刷完就断，不留常连
```

实测**握手那一层** 2.6 秒 → 0.3 秒。注意这是「一轮里 SSH 的开销」，**不是一轮的
总时长** —— 总时长由最慢的那个服务决定，所以服务一变慢，一轮就会变长（写这段时
`patches status` 一次要 12 秒，整轮 13.8 秒；把它优化到 2.4 秒后整轮 3 秒）。

`ControlPersist` **不要**设长：刷新间隔 30 秒，设成 60 秒等于对 Deck 保持一条常连。
**本项目不留常连、也不加隧道** —— 那种做法多一个会自己挂掉的进程，还会掩盖真实
原因（要绕问题先拿出对照实验级别的证据）。

> 这一条还有个**联动**值得知道：`ControlPersist=15s` 的「刷完就断」是靠
> 「一轮 ≪ 30 秒」成立的。服务变慢到一轮 13.8 秒时，15 秒的空闲窗口再也等不到，
> socket 就**事实上变成了常连**（实测 40 秒里每 3 秒采样一次，socket 一直在）。
> 把 `patches status` 优化回 2.4 秒之后，采样又能看到它「12 秒在 / 12 秒不在」了。
> 所以：**改慢一个服务的 status，会连带改掉 SSH 复用的行为**。

### 触发在 Deck、执行在 Mac

涉及「Mac 上的数据」的任务，让 Deck 只发信号、Mac 自己执行：Mac 才是数据所有者
（比如访达标签清单只在 Mac 上），Deck 不需要知道业务细节，只要能说「我醒了」。
这类入口一律**异步 + 并发去重**：Deck 随时可能休眠断网，让 SSH 连接只维持到
「请求被接受」，真正耗时的活儿丢到后台；去重是因为开机触发和唤醒触发可能挨得很近。

（早期 `backup` 服务用的「时钟差法检测休眠」等做法随它退役了，代码和说明见
`docs/历史-萤石NAS时期.md` 与 `_archive/`。）

## 4. Deck 侧

### systemd 用户服务

- 单位名：`deckkit-<服务名>.service`
- 放 `~/.config/systemd/user/`，用 `systemctl --user enable --now` 启动
- **不要**用系统级服务 —— 那需要 root，而且 `/usr` 会被 SteamOS 更新替换
- 非登录的 ssh 会话里没有 `XDG_RUNTIME_DIR`，`systemctl --user` 会失败 ——
  公共库的 `rsh_script` 已经统一补上，别各处再写一遍

### 文件位置

| 内容 | 位置 | 为什么 |
|---|---|---|
| 入口脚本 | `~/bin/deckkit-<服务名>-*` | 在 PATH 里，`ssh deck` 能直接调 |
| 服务源码 / 公共库 / 日志入口 | `~/deckkit/{services,bin}` | 和 Mac 侧结构对称，由各服务的 install 推上来 |
| 日志 | `~/deckkit/logs/<来源>.log`（见 §7） | 用户目录，持久 |
| 需要 root 的配置 | `/etc/...` | **注意**：`/etc` 是 overlay，SteamOS 大版本更新会清掉 → 一律用幂等的 provision 脚本重建，别手改 |

### root 操作

写一个 `provision-root.sh` 之类的脚本，**用 `sudo -n`（免密）**，检测失败就明确
提示怎么授权，不要交互式等待。免密 sudo 由用户在 Deck 上一次性授权
（Deck 没键盘鼠标时，用 `ssh -t deck` 从 Mac 把密码提示透传回来 ——
**任何需要人敲东西的步骤都应该从 Mac 发起**）：

```bash
ssh -t deck 'echo "deck ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/zz-deck-nopasswd >/dev/null; sudo chmod 440 /etc/sudoers.d/zz-deck-nopasswd'
```

`/etc/sudoers.d/` 里的文件名用 **`zz-` 前缀**：sudoers 规则是「最后匹配的生效」，
而 drop-in 按文件名字典序读取，`010-` 排在 `wheel` 前面会被它覆盖。

## 5. Mac 侧

- 图形界面启动的进程 **PATH 很窄**，不含 `/opt/homebrew/bin`。脚本里显式补 PATH。
- **绝不在主线程做同步网络/子进程调用**（菜单栏会卡死）。网络探测放后台队列并加
  超时；`ssh`/`curl` 也一样 —— 子进程要**边跑边读输出**，不能「等它退出再读」
  （管道塞满 64KB 之后子进程会卡在 write 上永不退出，见 §9）。
- 长任务入口（被 Deck 调用的那些）必须先拿锁再执行。
- **服务端渲染 / 后台任务发起的请求，用的是「服务端进程的网络身份」**，不是浏览器、
  也不是你敲命令的那个 shell。所以：
  - 配置里的地址要按「这台机器上的那个进程能不能访问到」来定；
  - **自检必须用「和那个进程同一个二进制」**：`curl`/`nc`/`ssh`/`python3` 是 Apple
    自带二进制、**不受** macOS「本地网络」权限限制，拿它们探会得到**相反**的结论
    （这个坑让我们白查了好几轮，还一度推翻了正确结论）。要探前端就用 `node` 探；
  - 别拿「我 curl 得通」证明「页面能取到数据」—— 要端到端测一次
    （做法：doctor 里真去请求一次那个页面看 SSR 有没有数据）；
  - 报错一定要把底层 cause 带出来（`fetch failed` 本身不含信息量），否则排查会
    退化成猜，甚至猜出一个错误的根因然后为它写出绕路代码。
  - 区分「连不上」的两种长相：`EHOSTUNREACH`（本地网络权限） vs `ECONNREFUSED`
    /超时（后端真没起来）—— 混在一起会互相误诊。
- **macOS「本地网络」权限**（macOS 15 起）：第三方二进制想连同网段主机，必须由
  「启动它的那个 App」拿到这个权限，否则 `connect()` 立刻 `EHOSTUNREACH`
  （errno 65，静默失败、不弹窗、不写日志）；网关和回环不受影响，Apple 自带二进制
  也不受影响。所以「从 shell 里一切正常、只有前端连不上」是它的典型长相。
  它**按 Mach-O UUID / bundle id 解析身份**：解析不到 bundle id 的上下文（比如终端）
  在系统设置里**连条目都不生成**，也就无法授权 —— 这种情况不要折腾那个列表。
- **拿不到权限就借有权限的 App**：`menubar/DeckKit.app` 是常驻的且已获该权限，所以
  「由它启动的 node」是通的。做法：需要局域网的服务在启动网络子进程前先探一次
  （**用和子进程同一个二进制探**），探不通就写请求文件 + `open -a <App> <文件>`，
  由 App 以自己的身份代跑（借用菜单栏 App 身份的那个入口；子进程带
  `DECKKIT_WEB_INAPP=1` 防递归）。父进程决定权限，**不要**改用常驻隧道绕。
- **休眠/唤醒是菜单栏状态的唯一「无声过期」来源**：Timer 睡眠期间不走，醒来只补
  一次。要订阅 `NSWorkspace.willSleepNotification` / `didWakeNotification`
  （token 必须持有），睡前标「检测中」、醒来立刻刷一次。

## 6. 安全阀优先

任何「会根据 Mac 的状态去删除 Deck 上东西」的逻辑，都要有退化保护。三道阀：

1. **清单为空** → 直接退出，什么都不做
2. **源不存在** → 跳过这一项
3. **源为空** → 跳过这一项

判断「空」要递归判断（`find "$SRC" -type f -print -quit`），因为「目录里没文件」
通常意味着磁盘没挂上或同步还没开始，而不是真的清空了。
**宁可不同步，也不要误删备份。**

同理，任何会**覆盖** Deck 上数据的操作（换数据库、换二进制、写 manifest、改单元文件）
都要先把现状另存一份再动手，并且**写"临时文件 + 原子 mv"**：半截写入留下的空文件
（一个空 manifest、一个空库）比报错难查得多。`rm -rf` 的变量必须有非空校验 +
路径前缀校验（`case "$p" in */store/*/*) …`）。

## 7. 日志

日志散在四处、各写各的（位置不同、格式不同、有的永不轮转）时，**排查的第一步
变成「先找日志在哪」，而不是看问题**。所以统一到一个入口：**`bin/deck-log`**
（Deck 侧是 `~/deckkit/bin/deck-log`，由各服务的 install 推上去）。不要自己拼日志路径。

| 机器 | 目录 |
|---|---|
| Mac | `~/Library/Logs/deckkit/<来源>.log` |
| Deck | `~/deckkit/logs/<来源>.log` |

（`DECKKIT_LOG_DIR` 可覆盖；Mac 用 `~/Library/Logs` 是因为那是系统惯例、访达能直接翻。）

```bash
deck-log <来源> "消息"             # 追加一条（自动加时间戳、压成一行）
deck-log <来源> <<'EOF' … EOF      # 从 stdin 逐行收录
deck-log --path <来源>             # 拿路径（要自己重定向的流式日志用）
deck-log --rotate <来源>           # 轮转：当前挪成 .1（流式日志启动时调）
deck-log --list                    # 列出所有来源、大小、最后一条
```

格式 `YYYY-MM-DD HH:MM:SS  <消息>`，一行一条（换行/tab 被压平）。**来源体现在
文件名里，不重复写在行首** —— 所以 `deck logs all` 可以按时间戳排完序再补上
`[来源]` 前缀，时间线才是准的。`<来源>` 只允许 `[a-z0-9-]`（会被规范化，
`../..` 跑不出日志目录）。

读：

```bash
deck logs                 # 菜单栏（默认）
deck logs <来源>          # 单个来源；本地没有就去 Deck 上 tail 一次
deck logs all             # 所有来源按时间合并
deck logs -f <来源>       # 实时跟
deck logs --list          # 有哪些来源、多大、最后一条
```

### 收录标准：只记对 debug 有用的东西

判断标准就一句：**这条记录能不能回答「当时发生了什么」**。

| 记 | 为什么 |
|---|---|
| **状态变化**（在线↔离线、服务挂载/启停、探测抖动） | 主线。「什么时候变的」是排查的第一问 |
| **失败 + 原始原因** | 没有原因就只能靠猜。ssh 的 stderr 必须带出来（`{"online":false,"why":"ssh: connect … timed out"}`），不能 `2>/dev/null` 扔掉 |
| **用户动作**（点了哪个服务、跑了哪条命令） | 「我什么都没干它就这样了」—— 日志要能证实或证伪 |
| **生命周期锚点**（启动/退出，带 PID） | 区分「没发生事件」和「进程根本没在跑」 |

| 不记 | 为什么 |
|---|---|
| 正常心跳（每轮都成功的探测） | 30 秒一行、一天 2880 行；翻开全是「一切正常」，真事被淹掉 |
| 数字波动（计数型，如索引条数） | 每轮都在涨，记下来等于心跳。菜单栏用 `normDigits` 抹掉「大数字 + 量词」再比较，但**记原始行** |
| 随时能重算的东西 | 状态随时能查（`deck status`），不必进日志 |

### 滚动

- **事件型**（经 `deck-log` 写）：按行数封顶，默认保留最近 **100 行**
  （`DECKKIT_LOG_MAX_LINES` 覆盖）。事件稀疏，100 条覆盖很久。
- **流式型**（node / proton 的原始输出，不走 `deck-log`）：**不按行裁**，
  改成启动时 `deck-log --rotate <来源>` 留一代（`.1`），并写一条**启动锚点** ——
  那些程序的输出不带时间戳，没有锚点就分不清哪段属于哪一次。

菜单栏是 Swift，没法为每一行去调 shell，所以自己写 `menubar.log`；但**路径、格式、
上限三个值刻意和 `deck-log` 一致**（`DECKKIT_LOG_DIR`/`DECKKIT_LOG_MAX_LINES`/
`DECKKIT_LOG_MAX_CHARS` 三个变量都读同一份）。

## 8. 改动纪律：先想连带影响，再动手

这一节是被真实事故逼出来的，核心就两句：**改一处之前先问「谁依赖它」，改完立刻实测一次。**

### 真实事故（同一天内发生的，都是同一个病）

| 改动 | 当时的想法 | 实际连带影响 |
|---|---|---|
| 往 `find-game-exe` 的排除表里加 `/Steam/` | "排除 Proton 自己的 `steam.exe`" | `grep -viE` 是**不分大小写**的，`/Steam/` 匹配上了 `~/.steam/steam/steamapps/…` —— 这段**每个 prefix 路径里都有** → 所有 exe 被滤掉 → 找主程序失败 → 记录与 Steam 注册全丢 |
| 删掉"安装器状态判据"整段 | "删掉多余的等待逻辑" | 顺手把同一段里的 **Ctrl-C trap** 一起删了；而注册挂在收尾后面、收尾又挂在阻塞调用后面 —— 用户 Ctrl-C 一次，收尾和注册全丢 |
| 用正则替换 `cmd_restore` 的实现 | "只改这一个函数" | 把夹在中间的 `cmd_remove` 一起删了 → 直接 `NameError` |
| 改"写完回读确认"的 glob | "只是换个写法" | 少了一个 `/`，glob 失效 → 明明写成功却报「回读不到」 |
| 用"合并所有备份"帮用户找回过丢失的条目 | "数据丢了就合并回来" | 把用户**主动删掉**的条目也复活了 —— 在用户视角里就是"你乱动我的列表" |

### 动手前先问五个问题

1. **谁依赖它？** —— 尤其是含 `grep -i` 的排除项/白名单：**先用真实路径跑一遍**再提交
2. **我删的这段里还有什么？** —— 删之前把整段读一遍，不要按标题删（trap、提示、别的函数都可能夹在里面）
3. **有没有第二处要同步改？** —— 例如改了 `meta.tsv` 的键名，所有读它的地方都要跟着改
4. **失败路径会怎样？** —— 阻塞调用被 Ctrl-C、文件被别的程序覆盖、路径不存在时：是**明确报错**，还是**静默丢结果**？（宁可吵，不可哑）
5. **这份数据是谁的？** —— 用户的 Steam 列表、游戏存档、原始补丁包：**宁可不动，也不要"帮忙恢复"**

### 改完必须做的三件事

1. **实测那条路径**（不是"看起来对"）：能真跑就真跑一次；不能真跑就把改动点和真实数据对一遍
2. **确认补丁真的落地**：`grep` 改动点；锚点没匹配上就**当失败处理**，别默认成功
3. **确认部署的副本是新的**：本地改了 ≠ Deck 上是新的（`install` / `install-here` 要跑，跑完再 `grep` 确认一次）
4. **判断"成功了没"要用不会骗人的信号** —— 别拿日志行数当判据：不设 `PROTON_LOG` 时
   Proton 会把 `DXVK_LOG_LEVEL` 设成 `none`，DXVK 一行都不打，实测"日志只有 2 行"的那几次
   其实已经渲染出窗口、game.exe 跑到 15% CPU（为此白查了一小时）；也别用 `strings | grep 名字`
   查二进制里的日文（`strings` 只输出 ASCII 串，必然查不到 → 会误报"没写进去"）。
   要么看窗口/CPU/退出码这种硬信号，要么把判据写在**不依赖编码、不依赖日志等级**的地方。

## 9. 踩过的坑（别重复踩）

跨服务、跨语言的硬坑。**服务自己的坑写在各服务的 `SERVICE.md` 里**，不往这儿堆。

| 坑 | 表现 | 解法 |
|---|---|---|
| IPv6 白等 / `.local` 解析慢 | 每次 ssh 慢 5 秒；`dscacheutil -q host -a name steamdeck.local` 主机在线也可能等满 5 秒 | `AddressFamily inet`；**运行路径上（菜单栏刷新、定时探测）用 IP**，只在手动命令（doctor）里解析名字 |
| 非交互 SSH 的 PATH | `ssh host 'cmd'` 找不到 brew 的命令 | 脚本里显式设 PATH |
| sudoers 顺序 | `010-xxx` 写了 NOPASSWD 却仍要密码 | 用 `zz-` 前缀 |
| SSH 超时 < 任务时长 | 误判失败并重复触发 | 改异步，或把超时设得比任务长 |
| **全角/中文紧跟 `$VAR`** | macOS 自带 bash 3.2 会把多字节字符的字节吃进变量名，报 `unbound variable`；`"（$VAR）"` 同理 | 一律写 `${VAR}`。Deck 上是 bash 5 不受影响，所以这个坑**只在 Mac 侧脚本**里暴露。`deck doctor` 会扫一遍所有脚本，别再手工找 |
| **`set -u` + 空数组** | bash 3.2 展开 `"${arr[@]}"` 报 unbound variable | 改用标量，或写 `"${arr[@]+"${arr[@]}"}"` |
| **`read -t` 的秒数** | bash 3.2 **不认小数秒**：`read -t 0.2` 报 `invalid timeout specification`，而且这条 read **直接失败** —— 在按键循环里表现成"方向键全部失灵"（很难往超时上想）；`read -t 0` 也不是"非阻塞读"，而是**立即失败**，会把 `ESC[C` 拆成孤立的 ESC，于是每按一次方向键都被当成 Esc | 超时只写**整数秒**。转义序列的后续字节本来就和 ESC 同批到达，整数超时下正常方向键感觉不到延迟，代价只落在"单独按 Esc"上 |
| **`$( … <<'EOF' … EOF )` 里的 `case`** | macOS 自带 bash 3.2 解析 `case … *)` 会错乱（同一段脚本在 bash 5 上完全正常），症状是 ssh 那一步莫名其妙失败 | 这种「把远程脚本塞进命令替换再喂给 `bash -s`」的写法里不要用 `case`，改用 `if` / `[ ]`；或者干脆走公共库的 `rsh_script`（脚本从 stdin 进来，不经过命令替换） |
| **管道会吞掉左边命令的失败** | `find … \| sort`、`ls … \| head` 整条的退出码来自**最后一个**命令，于是 `\|\| die "快照失败"` 永远不触发，空清单被当成「什么都没变」 | 判失败要拿**真源**的退出码：`out="$(cmd)"; rc=$?` 再判；别让管道替你做判断 |
| **先等子进程退出、再读它的输出** | 输出超过管道容量（macOS 64KB）时子进程阻塞在 write 上、**永不退出**，只能等满超时再把它掐掉 —— 于是「命令 0.02 秒就干完了」被报成「超时/检测中」 | 边跑边读（读线程 + 独立 deadline），超时只作兜底；Swift 侧见 `menubar/main.swift` 的 `run()` |
| **手动 close 一个别人拥有的 fd** | `close(fh.fileDescriptor)` 之后 FileHandle/NSFileHandle 析构会**再关同一个号**，而那个号早被另一个并发调用新开的管道复用 → 那个调用 `read` 拿到 EBADF，**输出为空但退出码仍是 0**（长相和「命令没输出」一模一样）。对照实验：320 次并发 32 次中招 | 自己 `dup()` 一份再关，或者用 `closeFile()`（有状态、不会重复关）；同理别用 `readDataToEndOfFile()`（超时路径上会漏 fd） |
| `scp` 传含 `~` 的路径 | SFTP 后端不保证展开 `~`，可能写进名为 `~` 的目录 | 用公共库的 `rsh_put`（内容走 stdin + 远端临时文件 + `mv`） |
| **`"${VAR#~/}"` 剥不掉前导 `~`** | 想剥掉 `~/` 却原样保留，拼出 `$HOME/~/...` | bash **也会**对 `${var#word}` 里的 word 做 tilde 展开（`~/` 被展开成 `$HOME/` 于是匹配不上）。写 `${VAR#\~}`。另注：参数以 `~` 开头时远端 shell 在 bash 看到它之前就已经展开了 |
| `ssh -t` 在无终端环境失败 | 菜单栏/CI 调用 `ssh -t` 直接报错 | 只在 `[ -t 0 ]` 时加 `-t`（公共库的 `rsh_tty` 已按这个规则） |
| **后台子进程继承调用者的 stdout** | `deck xxx web start \| tail` 之类的命令**永远不返回**（实测挂死 3 分钟） | `nohup cmd >>log 2>&1 </dev/null &` 只摘掉了 stdin。启动后台进程的那段要整体重定向：`( … & ) >/dev/null 2>&1`；想让 PID 落到真进程就 `( cd … \|\| exit 1; exec cmd … ) & echo $!` |
| `cfg_get` 里用 `xargs` 去空白 | 值里有单引号时 xargs 报错；连续空格被折叠；引号被当成语法吃掉 | 用 `sed 's/^[[:space:]]*//; s/[[:space:]]*$//'` |
| **`eval "$(…environ…)"` 读桌面会话凭证** | `XAUTHORITY` 含空格/引号/分号时破相（等于把陌生内容交给 shell 重新解析） | 逐行 `while IFS= read -r kv; do case "$kv" in DISPLAY=\|XAUTHORITY=\|WAYLAND_DISPLAY=*) export "$kv";; esac; done` |
| **脚本首行不是 shebang** | 命令行里**完全看不出来**：bash 执行一个不是可执行格式的文件时会自己回退成「按脚本读一遍」（POSIX 的 ENOEXEC 回退），于是 `./bin/deck files status` 一切正常、`bash -n` 也过；而用 `posix_spawn` 的调用方（菜单栏 App）拿到的是 `ENOEXEC`。症状是那一行**永远**显示「启动失败：… Exec format error」—— 而且看着像「服务坏了」，其实只是文件第一条不是 `#!`（真踩过：一次按索引切片改脚本，把新代码插到了文件最前面，shebang 被挤到第 49 行）。`deck doctor` 现在会扫这个，以及**同名函数定义了两次**（后者生效，看着改好了其实没有） |
| **拿字符串切片改脚本** | `s[a:b]` 里起点索引大于终点时 Python 返回**空串**，于是 `s.replace("", 新代码, 1)` 会把新代码**插到文件最前面**（不报错）。按「行号/索引」动脚本都会踩这类坑：改完必须回头看**首行是不是 shebang**、有没有重复定义，最好再 `bash -n` + 实跑一次 |
| **轮询正在编辑的脚本** | 菜单栏每 30 秒会 exec 一次各服务的 `service`，所以「正在写文件」的那一瞬间会被它抓到：半截文件 → `unexpected EOF`（rc=2，但 JSON 已经打出来了，看着很怪），或者没有 shebang → `ENOEXEC`。**改完再核对一次菜单栏那一行**；这种瞬时错误会自愈，但如果写坏的状态是**永久的**（比如 shebang 长期不在第一行），那一行就会一直错下去 |
| **逐文件 fork 外部命令** | 处理几千个文件时，`for f in ...; do md5sum "$f"; done` 这种写法把成本放在 **fork/exec** 上而不是干活上：实测 1748 次 fork = 6.4 秒 CPU（sys 3.8 秒），而真正的磁盘读量是 **0**（页缓存）—— 于是「慢」被误以为是 I/O 慢，往磁盘/文件系统方向查就查偏了 | 一次进程内批量做完（整批交给一个 `python3`/`awk`），或者至少用 `xargs -n 200` 把调用次数压下来。判断方法很简单：看 `time` 的 **sys 时间**占比 —— sys 远大于 user 基本就是 fork 太密 |
| **把「一轮多久」当成常量** | 类似 `ControlPersist=15s` 这种按「一轮 X 秒」标定的参数，会在某个服务变慢之后悄悄失效（详见 §3 那个联动） | 标定参数时把它依赖的那个量写成**可测的判据**（这里是「一轮的墙钟时间」），别只写结论 |
| **追加写日志时忘了结尾换行** | 两条记录黏成一行：`tail`/`grep` 按行取会连着取到两条，`deck logs all` 按时间戳排序时那一行会**排到错的位置**，而且错得看不出来 | 统一走 `deck-log`（它自己补 `\n`）；手写追加前先确认字符串结尾带换行 |
| **拿「日志里没有」当「没发生」** | 日志改成只记状态变化后，正常时段一行不写 —— 于是分不清「那会儿在正常探测」和「App 卡住没跑」 | 每个来源都要有**生命周期锚点**（启动/退出都带 PID）；判断进程在不在用 `pgrep`，别用日志安静与否 |
